# Nagram upstream and the t. overlay

The canonical app base is [NextAlone/Nagram-iOS](https://github.com/NextAlone/Nagram-iOS), currently `708d6692e8b19d9cdc660f13e3e034bc9691dee0`. `versions.json` records the revision. The initial imported snapshot was `db0722d6`.

t. keeps its independent branding, private API and signing configuration, App Store metadata, CI, and these Ayu features on top:

- Configurable Ghost Mode for read, typing/upload and online activity, with optional delayed cloud sending.
- Local preservation of deleted and edited messages, preservation rules, and history import/export.
- Locally loaded chats after leaving or being kicked.
- Optional secret-chat screenshots and local expiration of TTL media.
- Message filters, ad hiding, edited/deleted markers, and local Premium UI and limits.

AyuSync remains deferred. Screenshot notifications remain enabled; local Premium does not grant server subscription features.

Unrelated app behavior follows Nagram. UID-based developer/sponsor badges are removed, including their lookup lists, views, tooltips and localization. Keep this explicit downstream exception when syncing Nagram. The extra settings use t.’s native category menu and focused pages, with shared Nagram controls and preference keys. Keep this user-requested layout when syncing; existing setting links and search must still reach the right row. Startup, app navigation outside these extra settings, and notification behavior follow Nagram; the original fork’s About screen, agreement prompt, settings redesign and notification-test hooks remain removed. The original fork's combined chat filters, custom sorting, music controls, default text formatting, contact defaults, background-location notification fallback and extra account limits are removed. The app uses its signed notification service extension and normal APNs registration.

For every update, apply the changes after the recorded Nagram revision onto `master`, preserve this overlay and private configuration, and review overlaps. Keep the README's source attribution current without adding the former product name or restoring its removed feature list. Run a full app build with all six signed extensions before accepting a release. Never merge upstream commit history into the reset public history or publish a compiled app, clear compiler cache, identifiers or credentials as a public artifact.

## Daily hosted sync

`upstream-sync.yml` runs on GitHub Actions daily at 03:23 UTC (12:23 Japan time), with manual dry-run and live-model smoke-test options. The local Codex heartbeat is disabled. No local checkout or computer is needed for scheduled work.

`ci/sync-upstream.py` compares complete tree snapshots at the recorded revision and upstream HEAD, applies a three-way merge, and asks free coding models through OpenRouter to resolve overlapping text hunks and review all proposed source deltas. The model order is Laguna S 2.1, Nemotron 3 Ultra, then North Mini Code, using only their `:free` endpoints. Prompt and completion price ceilings are both zero; there is no paid fallback. Each run permits at most 18 model calls. An unavailable provider, incomplete response or disputed decision is retried with another free model. Reviewers can return bounded exact text corrections, which are applied and reviewed again automatically. Decisions are parsed as data; no model tool is executed. Only public source reaches the model. If free quota, validation or infrastructure still prevents a valid candidate, publication stays unchanged and the next daily run retries automatically. No merge decision requires human approval.

The model job has read-only repository access. A separate publisher validates ownership, credentials, existing settings/callbacks/category links, release configuration and concurrent master/upstream changes before creating one commit with only the existing public master as its parent. Upstream guidance files (including `CLAUDE.md`), documentation, CI, release scripts and private configuration are skipped automatically. App code, Bazel/build infrastructure and toolchain versions follow upstream. App version and release identities remain t.'s. Renames carry the downstream overlay to the new path; downstream removals stay removed and upstream removals retain locally modified overlay files. Untouched binary assets follow upstream; overlapping binary edits retain t.'s asset. Executable modes, safe source symlinks and dependency pointers are preserved. Changed dependencies are hydrated from a pinned recursive upstream checkout for native validation. Complete tree comparison also handles rewritten history and changes beyond GitHub's 300-file compare limit. README edits are preserved apart from the source revision. The publisher explicitly dispatches the signed build because pushes made with `GITHUB_TOKEN` do not trigger push workflows. An existing active release is preserved.

The daily job also resumes and audits the latest exact iOS TestFlight train, even without new upstream commits. It preserves pending beta review, verifies both audience attachments, checks the rendered public join page, and attaches the eligible build to the App Store version only while it is in Prepare for Submission. Signed CI performs the same external-beta continuation immediately after upload. No workflow publishes privacy declarations, submits an App Store review, invites individual testers or changes review credentials. Apple approval remains separate from upload success.

Settings reorganizations use whole-file context with bounded exact text replacements, avoiding a full-file model rewrite. Every old setting row/callback, category entry point and localization key remains protected, and review includes the expected upstream delta to catch omitted behavior. A missing build dispatch is reconciled against existing source-specific runs before creating one; a failed current release cannot be hidden behind an older live beta. An already uploaded exact eligible build is retained even if its CI monitor failed.

Before a source snapshot reaches master, a separate hosted Xcode job applies the reviewed proposal to an ephemeral checkout and completes a full formal `release_arm64` build with all six extensions and strict signing verification. Its validation build is never uploaded. Only then may the publisher update master and dispatch the shipping build; the encrypted compiler cache can be reused. Compiled apps remain on ephemeral runner storage and are never public artifacts.
